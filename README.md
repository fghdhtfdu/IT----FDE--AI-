从“能做”到“该做”——AI产品落地的场景工程与渐进式架构
AI产品落地最根本的困境，不在于模型能力不够，而在于选错了要解决的问题。超过60%的企业AI尝试停留在实验阶段，瓶颈不在Demo，而在于从Demo到生产之间存在一道极宽的鸿沟——系统对接、权限梳理、流程改造、合规审计、组织适应，每一项都需要工程化的解决方案。

场景选择是最被低估的决策点。 不是所有业务问题都适合用大模型解决。企业在启动AI项目前，需要建立一套场景评分机制，从业务价值、数据就绪、技术可行性、组织采用、实施风险和可复制性等维度进行量化评估。核心判断标准不是“能不能做”，而是“值不值得进入生产”。

渐进式架构是降低落地风险的关键策略。 OpenAI与Google超过50个企业级AI项目的复盘经验揭示了一个核心教训：大多数团队从一开始就构建“能自主学习、多步骤推理、调用十几个工具”的超级Agent，最终陷入系统不稳定、输出不可控的困境。更务实的路径是分阶段推进——先从单次交互的提示词工程解决明确受限的问题，再引入检索增强（RAG），最后根据验证结果决定是否升级为Agent架构。

“可计算对象”是场景落地的技术前提。 某航空公司航线效益项目的案例揭示了关键方法：AI的起点不是模型，而是先将复杂业务拆解为可计算、可追溯、可比较的数据结构。该项目将航班成本项从千余项细化到数千条计算规则，使管理层能在运力仍可调整时看到接近实时的成本与收益。这种对业务的精细化拆解，是所有AI产品落地的技术底座。

对于FDE而言，核心能力不是在最短时间内搭出一个Demo，而是判断哪些问题值得进入生产、用什么架构支撑、如何分阶段验证价值。
